# M9: Write-up

**Goal:** turn the project into a three-minute story you can tell in an interview.

**You'll learn:** technical documentation and change management, the two things the posting asks for that are easiest to show on paper.

## Build

- **Update `README.md`:** what each part does, how to run it, the decisions you made and why (staging plus MERGE, the watermark, a timer Function), and what you'd do next.
- **`docs/change-request-example.md`:** write a change request for "add a `pronouns` field to students": what changes, why, risk, who is affected, test plan, rollback plan, deploy window.
- **Screenshots:** the Power BI report, a green CI run, a successful run in `core.pipeline_runs`.

## Done when

- [ ] Someone else could clone the repo and run it from the README
- [ ] You can walk through the whole system out loud in three minutes without notes

**Interview line:** "I can walk you through it. Here's the architecture, here's why I made each choice, and here's what I'd change at real scale."
